<p>新手来问的时候，问题通常是连着的：先问到底要不要买，接着问买哪种形态，然后问怎么配到电脑和路由器上，配好了又问一条线能挂几个号，最后问出异常该从哪儿查。这五个问题串起来其实就是一条完整的上手路径。下面按这个顺序一条条往下答，每个问题给判断依据、常见错答和可执行动作，中间穿插两张表，方便边看边对照自己的情况。</p>

<h2>一、第一个问题：到底要不要买，先算需要几条</h2>
<p>不要先看套餐，先数账号和行为。数清楚了，需要几条线路是算出来的，不是猜出来的。</p>
<h3>按“同时在线的账号数”起步</h3>
<p>经验做法是一个长期运营的账号配一条固定出口，同一出口上不要挂多个需要长期保持登录态的关键账号。三个这样的账号，起步就是三条。临时测试用的号可以共用一个池，但不要和关键账号混在同一地址上。</p>
<h3>常见错答：一条线挂十个号更省钱</h3>
<p>省的是租金，付出的是关联风险与排障难度。一旦这条地址出问题，十个号一起受影响，且很难判断是哪个号引起的变化。真要省，宁可减少账号数量，也不要压缩出口数量。</p>

<h2>二、第二个问题：买什么形态，独享、静态还是池</h2>
<p>形态选择取决于账号的寿命预期和操作频率，不取决于价格排序。</p>
<h3>长期固定 vs 短期轮换</h3>
<p>需要长期保持登录态、有对外服务、或者要接内部系统的，选静态独享；一次性采集、短期验证、批量注册类的任务，用池更经济。混着用是最常见的浪费——关键账号跑在池上，地址天天变，体验必然差。</p>
<h3>地区怎么定</h3>
<p>三条依据：账号注册地、主要使用者所在时区、目标服务的地区覆盖。三者尽量一致。给一个东八区用户配西欧出口，每次登录的时间分布都很反常，属于自找麻烦。选定后用 ipinfo 核对 city 与 ASN，确认与实际一致。</p>

<h2>三、第三个问题：怎么配到电脑和路由器</h2>
<p>配置本身不难，难在把“配好了”验证清楚。建议先在一台机器上打通，再复制到其他设备。</p>
<h3>Windows 与浏览器的两种接法</h3>
<p>系统级代理在“设置—网络和 Internet—代理”里填地址与端口，影响面大但粒度粗；浏览器级用启动参数 --proxy-server="http://地址:端口" 加独立的 --user-data-dir，粒度细、互不干扰，适合多环境并行。两种接法都要用 curl -x 或页面查询接口验证出口，别只看面板提示。</p>
<h3>路由器接法适合固定场所</h3>
<p>把线路配在路由器的 WAN 或策略路由上，下游设备无需单独设置。要点是给关键设备做 DHCP 静态绑定，并在路由表里明确哪些网段走这条出口。配完用 tracert 看第一跳是否落在预期网关，再看出口地址是否变化。</p>

<h2>四、第四个问题：账号怎么分组，一条线挂几个号</h2>
<p>分组的目的不是整齐，而是把风险隔开：一组出问题，不影响另一组。</p>
<h3>按业务重要度分三组</h3>
<p>核心组（对外服务、长期客户）配独享静态、单独出口；常规组（内部日常使用）配独享静态、可共用一两条线路但按人分开；测试组（临时验证）用池，用完即弃。三组的配置、凭据、监控都要分开，不要交叉。</p>
<h3>按操作时段错峰</h3>
<p>同一出口上的多个账号，尽量把活跃时间错开。全部集中在同一小时操作，流量曲线和会话节奏都很一致，这种一致性本身没有好处，只会让排障时更难区分。分组表建议直接写进运维文档，见下表。</p>

<h2>五、第五个问题：出事怎么排查，四步走完</h2>
<p>异常提示五花八门，排查顺序却可以固定。四步走完，八成问题能定位到具体一层。</p>
<h3>第一步：确认出口，第二步：确认解析</h3>
<p>先 curl -x 打 ipinfo，看 ip、org、country 是否符合预期；再用 dig 指定 DNS 查一个域名，确认解析没有走本地。这两步能在两分钟内排除最常见的两类问题。</p>
<h3>第三步：确认时区语言，第四步：确认账号侧</h3>
<p>在控制台看 Intl.DateTimeFormat().resolvedOptions().timeZone 与 navigator.language，与出口地区比对；若前四步都正常仍有异常，就要考虑账号自身状态，比如近期是否改过密码、是否在多地下登录。此时应查登录记录，而不是继续折腾网络。</p>
<h3>把结论写进值班手册</h3>
<p>每次排查完记一句“现象—定位—处置”，三个月后这份记录就是最有用的手册。新人上手时按手册走，比口口相传稳定得多。</p>

<h2>常见问答</h2>
<h3>预算有限，先买几条？</h3>
<p>答：先买能覆盖核心账号的数量，测试组用共享池顶着。核心账号的稳定性带来的收益，通常高于多买几条线路省下的那点钱，顺序别搞反。</p>
<h3>电脑配好了，手机还要单独配吗？</h3>
<p>答：要。手机走的是自己的网络栈，电脑上的系统代理不会自动生效。可以装在路由器上让手机共享，也可以在手机端单独配置代理，两者选其一并记进文档。</p>
<h3>一条线路能同时几台设备用？</h3>
<p>答：技术上看端口与并发限制，业务上看账号绑定关系。若这些设备登录的是同一批账号，多设备同时在线本身就容易触发额外验证，建议按设备分线。</p>
<h3>换线路后账号需要做什么？</h3>
<p>答：不要同一天既换出口又改密码。先换出口，观察两三天，确认登录正常后再做其他变更。多个变量同时动，出问题时无法归因。</p>
